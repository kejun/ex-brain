🧬 本体建模（Ontology Modeling）—— 知识库的骨架

🧬 本体建模在 ebrain 中的核心作用

本体建模（Ontology Modeling）是 ex-brain 将非结构化文本转化为结构化知识图谱的核心机制。它定义了「知识由什么构成」——实体（Entity）、关系（Relation）、类型（Type）和事实（Fact）的组织方式。在 ebrain query --llm 的执行链路中，本体建模贯穿始终，决定了检索、上下文构建和回答生成的质量。

本体建模如何影响 query --llm 的执行

▼
①

写入阶段：LLM 驱动的自动本体构建

当用户通过 smart-ingest 或 put 写入内容时，applyEntityLinks() 调用 LLM 提取实体和关系：

原始文本 → extractRelations() 实体抽取 → entityToSlug() 命名空间归位 → ensureEntityPage() 创建/更新实体页 → link() 写入关系边
关键点：实体类型识别（中英混合关键词匹配）、消歧（findSimilarSlug 语义搜索找已存在实体）、关系置信度过滤（默认阈值 0.7）共同保证了本体质量。
②

检索阶段：类型加成（Type Boost）影响排序

在 query() 混合评分中，本体类型直接影响检索排名：

const typeBoost = String(md.type ?? "") === "person" ? 0.05 : 0; const score = vectorScore * 0.85 + freshnessBoost + typeBoost;

人物类型获得 +0.05 加成，因为人名通常是知识图谱的核心节点。本体类型还存储为向量集合的 metadata，支持 search --type company 按类型过滤。

③

上下文构建：关系图驱动的 Linked Pages 扩展

在 collectContextForLLM() 的 Layer 3 中，系统沿着本体关系图扩展上下文：

top hit 页面 → outgoingLinks() 出边 → backlinks() 入边 → keyword 相关度过滤 → 加载关联页面上下文
关键点：这使得查询「张三的公司」时，不仅返回张三页面，还能通过关系图自动关联到他创立的公司页面，无需在问题中显式提及公司名。这是知识图谱对比传统检索的核心优势。
④

LLM 回答：结构化溯源引用

Prompt 中要求 LLM 使用 [[slug|标题]] 格式引用来源，而 slug 本身携带本体语义：

📄 1. [[companies/river-ai|River AI]] - 页面正文 📄 2. [[people/zhang-san|张三]] - 页面正文 🔗 3. [[people/li-si|李四]] - 关联页面: people/li-si (72.3%)

用户通过 slug 路径（如 companies/, people/）即可判断信息的本体类型，实现可溯源、可验证的知识回答。

⑤

消歧与实体对齐

findSimilarSlug() 通过语义搜索解决实体冲突（如「张三」和「张叁」是否同一人），置信度阈值 0.9 避免误匹配。这保证了知识图谱中不会出现重复节点。

关键点：本体建模不是一次性的——每次 ensureEntityPage() 都会检查去重（compiledTruth.includes(trimmedContext)），同一事实不会重复添加，保证知识的一致性。

💡 关键设计要点
1

本体建模是核心骨架

从写入（自动抽取实体关系）到检索（类型加成排序）到上下文（关系图扩展）到回答（溯源引用），本体贯穿全链路，将散落的文本转化为可推理的知识图谱。

2

三层上下文采集

Primary → Raw → Linked 的渐进式采集，Linked pages 通过关系图自动发现关联知识。

3

预算截断机制

100K 字符上限，自动截断防 token 超限。

4

混合评分模型

向量 × 0.85 + 新鲜度 + 类型加成，兼顾语义匹配和时效性。

5

来源溯源 + 消歧对齐

[[slug|标题]] 引用 + findSimilarSlug 语义消歧，保证知识可验证、不重复。
